## 1. 概述

### 1.1 产品定位

lumen 是一款**本地优先（local-first）的单机桌面工具**，面向学生与教师，核心价值是：把"教材"变成**可查询、可练习、可测评、可讲解**的私有知识库。所有 AI 能力（出题、答疑、总结、阅卷）都以教材内容为依据，可溯源到"第几章第几页第几段"。

### 1.2 目标用户与典型场景

| 用户 | 典型场景 |
| --- | --- |
| 学生（自学/备考） | 导入教材 → 按章节生成知识总结 → 生成测验 → 应用内作答 → 查看成绩单与错题 |
| 教师（备课/出题） | 导入参考书 → 按章节出题 → 组卷导出 PDF → 生成教案 → 课堂答疑演示 |

**用户故事（选摘）**

- 作为学生，我希望把 PDF 教材导入应用并自动分章，这样我可以按章节学习。
- 作为学生，我希望答疑时答案带着教材引用，这样我可以核验 AI 没有胡说。
- 作为教师，我希望按章节、题型、难度生成题目并先审校再使用，这样题目质量可控。
- 作为教师，我希望主观题能 AI 阅卷并给出得分点点评，这样我能快速批改。
- 作为隐私敏感用户，我希望数据全部留在本地，且自建本地模型后可离线运行。

### 1.3 设计原则

1. **本地优先**：数据在本地 SQLite / 文件系统；用户自建本地模型后，核心链路可完全离线运行。
2. **教材即知识库**：一切 AI 产出可溯源到章节、页码、段落。
3. **AI 任务即工作流**：每个能力都是"选范围 → 选模型 → 生成 → 人工校对 → 存档"的统一流程。
4. **可干预**：AI 产出物全部可编辑、可保存、可导出，不追求全自动。
5. **可审计**：每次 AI 调用记录模型、token、耗时、成本估算。
6. **可备份**：整个知识库可导出为单一归档文件（.lumen）。

### 1.4 范围边界

| 做 | 不做（P3 之后再评估） |
| --- | --- |
| 单机单用户桌面应用 | 多人协作、班级管理、账号体系 |
| 云端 API（BYOK）+ 用户自建本地模型 | 云端同步（除非用户自建同步盘） |
| 应用内作答 + 打印纸笔作答后录入 | 移动端 App |
| 教材：PDF 为主，含 DOCX/MD/TXT/EPUB | 视频/音频教材 |

## 2. 核心概念模型

```
Course 课程
 ├── 元信息：名称、科目、封面、学期、描述、状态（在用/归档）
 ├── Textbook 教材（1..n）
 │    ├── 源文件（PDF / DOCX / Markdown / TXT / EPUB）
 │    ├── 解析状态、页数、字数、结构来源（书签/样式/自动/人工）
 │    └── Chapter 章节（树形：章 → 节 → 小节，1..n）
 │         ├── 标题、层级、页码范围、原文内容（段落块）
 │         ├── ChapterChunk 段落块（向量化与引用的最小单元，n..n）
 │         └── KnowledgePoint 知识点（自动抽取或人工维护）
 ├── Exercise 习题
 │    ├── 范围：章节 / 教材 / 全部教材；题型；难度；来源引用
 │    └── （草稿箱 → 发布 → 题库）
 ├── Paper 试卷 ── PaperQuestion ── Exercise
 │    └── Attempt 作答记录 → Answer → AI 阅卷结果（得分点、扣分、建议）
 ├── Summary 知识总结（章节级笔记，多版本）
 ├── LessonPlan 教案（多版本）
 └── Session 答疑会话（学生 ↔ AI 教师，消息带引用）

全局资源：
  Model（模型配置）、PromptTemplate（提示词模板）、AITask（任务记录）、Settings
```

**关键设计决策**：引入 `ChapterChunk` 作为检索与引用的最小单元（通常为自然段落，标注页码与段落号）。答疑引用、出题溯源都落到 chunk 级，而非整章。

## 3. 功能模块设计

### 3.1 课程管理
- 课程 CRUD、归档；一门课程可导入多本教材（主教材 + 参考书）。
- 课程视图：左侧教材/章节树，右侧内容区；支持多标签页同时打开章节。
- 全局搜索：跨教材全文检索（FTS5）+ 语义检索（向量），结果带出处。

### 3.2 教材导入与拆分
- **导入**：PDF 为主，支持 DOCX / MD / TXT / EPUB；加密 PDF 需用户输入口令；损坏文件明确报错。
- **解析管线**：文本抽取 → 结构识别 → 章节树生成 → 分段 → 向量化入库 → 关键词/知识点提取。
- **扫描版 PDF**：文本提取率 < 5% 时提示"检测到扫描件，是否启用 OCR"；OCR 为可选异步步骤（Tesseract / PaddleOCR）。
- **拆分策略**：
  - 优先依据文档原生结构（PDF 书签、DOCX 标题样式、MD 标题）；
  - 无结构时：按页码/字数阈值自动切分，再用 LLM 为每段生成标题；
  - 提供章节编辑器：拖拽调整、合并、改名、重新划界（改动后自动重向量化受影响章节）。
- **大文件**：异步任务、进度条、断点续跑（任务表持久化当前页码等断点字段）、可取消。

### 3.3 习题与测试卷
- **生成范围**：章节 / 整本教材 / 课程全部教材，支持多选交集。
- **参数**：题型（单选/多选/判断/填空/简答/计算/论述）、数量、难度梯度（1-5）、是否配解析与参考答案。
- **草稿箱审校**：编辑、删除、重新生成单题、标记质量（👍/👎 用于回溯模型效果）。
- **组卷**：设定时长、分数分布、题序随机、选项打乱（固定随机种子，可复现）。
- **导出**：试卷 PDF（含答题卡）+ 单独导出答案卷 PDF。
- **作答与 AI 阅卷**：
  - 客观题：规则判分（归一化后精确匹配），即时出分。
  - 主观题：应用内文字作答，AI 按"参考答案 + 评分细则"评分，输出得分点逐条点评、扣分原因、改进建议；支持"重新评阅"（换模型或追加要求）。
  - 纸笔作答：导出 PDF 打印作答后，在应用内手动录入答案，走同一阅卷流程。
- **成绩单**：得分、用时、逐题点评、知识点掌握度雷达图（按章节，P3）。

### 3.4 知识总结（章节笔记）
- 按章节生成：知识框架（大纲）、核心概念定义、公式/定理清单、易错点、思维导图（文本版 / 可导出 Markdown + Mermaid）。
- 多版本保存，可对比；支持"总结 → 生成测验题"一键联动。

### 3.5 教师答疑（AI 教师）
- 对话式，**强制 RAG**：先从选定范围（本章节/本教材/全课程）检索相关段落，再作答，答案必须带引用（教材名、章节、页码/段落号）。
- 模式：直接给答案 / 苏格拉底式引导（先提示不直接给）/ 批改学生思路。
- 对话可收藏为"答疑卡片"存入笔记；引用可点击跳转原文段落。

### 3.6 教案生成（教师）
- 输入：章节、教学目标、课时长度、学生学情（可选）、教学法偏好。
- 输出：教学目标、重难点、教学过程（导入/讲授/练习/小结）、课堂提问、随堂测题、作业布置。
- 教案与题库打通：随堂测题直接从题库挑选。

### 3.7 模型管理
- 所有模型（文本/嵌入/重排）统一经 OpenAI 兼容网关接入：默认调用云端 API（用户自带 Key）；用户也可自行部署本地模型（Ollama / LM Studio / llama.cpp），以完全相同的方式配置使用。应用不内置任何模型。
- 可视化增删改模型：测试连通性、测上下文长度、标注能力（文本/视觉/长文/嵌入）。
- 任务级模型选择：每个 AI 任务下拉可选模型，并记住"该任务上次使用的模型"。
- 默认模型策略：按任务类型设默认（如答疑默认长上下文模型）。
- Key 本地加密（AES-256-GCM，主密钥放系统钥匙串）；用量统计（token / 费用估算）。

### 3.8 任务中心（P0）
- 统一展示全部异步任务：教材导入、向量化、出题、阅卷、总结生成等。
- 每个任务：类型、状态、进度条、日志、耗时、token 用量、可取消/重试。

### 3.9 错题本与学情分析（P3）
- 错题自动归入错题本，可按知识点/章节筛选，可针对错题再生成同类题。
- 知识点掌握度雷达图、薄弱点推荐、学习计划雏形。

### 3.10 数据备份与导出（P3）
- 一键导出 `.lumen` 归档（SQLite + 原文文件 + 配置），支持从归档恢复。
- 全部内容可导出为 Markdown / JSON。

## 4. 关键流程

### 4.1 教材导入流程
```
选择文件 → 格式检测 →（加密？→ 请求口令）→ 文本抽取（扫描件 → 可选 OCR）
 → 结构识别（书签/标题样式）
   ├─ 成功 → 生成章节树 → 人工确认
   └─ 失败 → 自动切分 + LLM 拟标题 → 人工确认
 → 分段（ChapterChunk）→ 混合检索索引（FTS5 + sqlite-vec）→ 知识点抽取 → 完成
异常：解析失败 → 记录错误 + 保留原文文件，允许重试/手动补录
```

### 4.2 出题流程
```
选范围（章节/教材/全部）→ 设题型/数量/难度 → 选模型
 → 生成（流式输出，逐题出现；JSON Schema 约束 + 校验层自动重试 ≤2 次）
 → 草稿箱审校（编辑/重生成/删除/质量标记）
 → 发布：保存到题库 / 组卷导出 PDF / 直接测验
```

### 4.3 答题阅卷流程
```
开始测验（计时，配置快照）→ 作答（客观题点选，主观题文本）
 → 提交 → 客观题规则判分（即时）
        → 主观题 AI 阅卷（并行逐题，temperature=0）→ 得分点点评
 → 成绩单 + 知识点掌握度分析 → 错题自动归入"错题本"
纸笔路径：导出试卷 PDF → 打印作答 → 应用内录入答案 → 同一阅卷流程
```

### 4.4 答疑流程（RAG）
```
学生提问 → 解析检索范围 →（可选）查询改写
 → 混合检索（BM25 ∪ 向量，RRF 融合 top-20）→ 交叉重排（reranker）→ top-5
 → 拼接原文片段（带出处标签）+ 问题 + 多轮历史 → 模型流式作答
 → 引用抽取与校验 → 展示答案 + 可点击引用
 → 追问（多轮，带历史）/ 无出处内容强制声明"教材未覆盖"
```

### 4.5 离线模式切换
```
用户自行部署本地模型（Ollama/LM Studio）→ 在模型管理中按云端模型同样方式配置
 → 连通性测试 → 各任务默认模型切换为本地模型
 → 全部 P0/P1 链路离线可用（前提：本地已部署嵌入 + 文本模型）
```

## 5. 技术架构

### 5.1 分层架构

```
┌────────────────────────────────────────────────────────┐
│  桌面外壳：Electron（主进程 + 渲染进程）               │
│  · 窗口/菜单/托盘 · 系统对话框 · 自动更新              │
│  · 进程管理：启动/守护 Python sidecar                  │
├────────────────────────────────────────────────────────┤
│  前端 SPA：React 18 + TypeScript + Vite                │
│  · 页面/组件 · 状态（Zustand + TanStack Query）        │
│  · 经 localhost HTTP + SSE 与 sidecar 通信             │
├────────────────────────────────────────────────────────┤
│  本地服务层：Python 3.12 + FastAPI（sidecar）          │
│  · 任务编排 · RAG 检索 · 文件解析 · OCR · 向量化       │
│  · LLM 网关（OpenAI 兼容抽象）· 阅卷/出题/总结         │
│  · 仅监听 127.0.0.1:随机端口，令牌认证                 │
├────────────────────────────────────────────────────────┤
│  存储层                                                │
│  · SQLite（WAL）：课程/章节/题目/记录/任务/设置        │
│  · sqlite-vec 虚拟表：段落向量（与业务数据同库）       │
│  · FTS5 虚拟表：全文索引                               │
│  · 文件系统：教材原文、导出物、.lumen 备份             │
├────────────────────────────────────────────────────────┤
│  模型层                                                │
│  · 云端：OpenAI / DeepSeek / 通义 / 智谱 / Claude 等   │
│  · 本地：用户自建 Ollama / LM Studio / llama.cpp       │
│  （经统一网关接入，与云端模型使用方式一致）            │
└────────────────────────────────────────────────────────┘
```

### 5.2 进程模型与通信

- **Electron 主进程** 负责：窗口/菜单/托盘/系统对话框、自动更新（electron-updater）、启动并守护 sidecar；OS 钥匙串由 sidecar 的 keyring 库跨平台承担。
- **Python sidecar** 负责：全部业务逻辑。启动时由 Electron 主进程分配随机端口与一次性启动令牌，写入仅本机可读的临时文件；前端通过 Electron IPC 获取连接信息后直连 sidecar HTTP（SSE 流式输出因此原生可用）。
- **大文件传输**：不经过 HTTP body，走文件系统路径传递。
- **CPU 密集型工作**（OCR、PDF 解析）放入进程池，避免阻塞事件循环；本地模型推理由用户自建的模型服务进程承担。

### 5.3 模块划分

**后端（backend/app）**

| 模块 | 职责 |
| --- | --- |
| api | REST 路由、SSE 端点、参数校验（Pydantic） |
| services/parsing | 教材解析：PDF/DOCX/MD/TXT/EPUB、OCR、结构识别、章节树 |
| services/indexing | 分段、FTS5、sqlite-vec 向量化、知识点抽取 |
| services/rag | 检索、重排、上下文组装、引用校验 |
| services/ai | LLM 网关（Provider 抽象）、出题、阅卷、总结、教案协议 |
| services/jobs | 异步任务队列（状态机、进度、取消、重试、断点） |
| services/export | Typst 渲染 PDF、Markdown 导出、.lumen 归档 |
| models | SQLAlchemy 模型 + Alembic 迁移 |
| core | 配置、加密、日志 |

**前端（frontend/src）**

| 模块 | 职责 |
| --- | --- |
| pages | 课程/教材浏览、题库、测验、答疑、教案、模型管理、任务中心、设置 |
| components | 章节树、草稿箱、引用卡片、雷达图、向导（出题 4 步） |
| api | 后端客户端（TanStack Query 封装、SSE 订阅） |
| stores | Zustand（UI 状态、任务状态） |

### 5.4 目录结构

```

├── backend/              # Python sidecar
│   ├── app/

│   │   ├── services/     # 解析/索引/RAG/AI/任务/导出
│   │   ├── models/       # SQLAlchemy + Alembic
│   │   └── core/         # 配置/加密/日志
│   └── requirements.txt
├── frontend/             # React SPA
├── templates/            # Typst 试卷模板、Prompt 模板内置副本
└── dist/                 # 打包产物（dmg / msi / AppImage）
```

## 6. 技术选型

### 6.1 选型总表

| 组件 | 选择 | 备选（未选） | 决策理由 |
| --- | --- | --- | --- |
| 桌面外壳 | **Electron**（主进程 + 渲染进程） | Tauri 2.x | 自带 Chromium，渲染一致性最好；Windows 无需 WebView2 引导、Linux 兼容最稳；生态成熟。体积/内存代价因已内嵌 Python sidecar 而弱化 |
| 前端框架 | **React 18 + TypeScript + Vite** | Vue 3 / Svelte | 生态成熟、组件库丰富（shadcn/ui）、团队熟练度高 |
| UI 组件库 | **shadcn/ui（Radix 原语）** | Ant Design / MUI | 可定制、无运行时依赖、深色主题友好，适合本地工具 |
| 服务端状态 | **TanStack Query + Zustand** | Redux Toolkit | 查询缓存/重试/SSE 增量更新开箱即用；Zustand 轻量 |
| 本地服务层 | **Python 3.12 + FastAPI** | Rust（axum） | PDF/OCR/嵌入/LLM 生态几乎全部在 Python；HTTP 边界清晰，未来可整体替换为 Rust |
| PDF 解析 | **PyMuPDF（fitz）** | pdfplumber / PDFMiner | 速度最快，同时提供文本、书签、图片、坐标；pdfplumber 保留为复杂表格兜底 |
| 扫描件 OCR | **PaddleOCR（PP-OCRv5）** | Tesseract（chi_sim） | 中文识别率显著更高；Tesseract 依赖小，作为轻量备选/降级方案 |
| 向量检索 | **sqlite-vec** | Chroma / FAISS | 与 SQLite 同库、零额外进程、单文件；FTS5 可同库做混合检索；FAISS 增删改管理成本高 |
| 全文检索 | **SQLite FTS5（BM25）** | Meilisearch | 内嵌、零运维，与向量检索同库融合 |
| 嵌入/重排模型 | **不内置**，由用户在模型管理中配置 | 内置 bge-m3 / bge-reranker | 避免体积与 CPU 性能负担；用户自建或云端模型经统一网关以同等方式接入，云端/本地体验一致 |
| LLM 接入 | **自研 Provider 抽象层，统一 OpenAI 兼容协议** | LangChain | 直接控制流式输出、结构化输出、成本统计；避免框架抽象泄漏 |
| 数据库 | **SQLite（WAL 模式）** | PostgreSQL | 单机单用户无需服务端数据库；单文件易备份；Alembic 管理迁移 |
| 任务队列 | **asyncio + SQLite 任务表** | Celery / Redis | 本地单机无需重型中间件；任务状态持久化支持取消/重试/断点续跑 |
| PDF 导出 | **Typst（便携二进制）** | WeasyPrint | 排版质量与 CJK 支持更好、渲染快；备选 WeasyPrint（纯 Python，无额外二进制） |
| Key 加密 | **AES-256-GCM + OS 钥匙串** | 仅配置文件加密 | 主密钥不落盘；macOS Keychain / Windows 凭据管理器 / Linux Secret Service |
| 公式渲染 | **KaTeX（前端）+ Typst（导出）** | MathJax | 速度快，导出与显示一致 |
| 测试 | **pytest + vitest + Playwright** | unittest / Cypress | 前后端标准组合 |
| 打包分发 | **electron-builder**（dmg/msi/AppImage） | Tauri bundler | 与外壳一体 |

### 6.2 关键决策论证

**（1）桌面外壳：Electron**
- Electron 自带 Chromium：渲染一致性最好，Windows 无需 WebView2 引导，Linux 兼容最稳——这是 Tauri 方案的主要风险点。
- 体积（~150MB）与内存代价在本项目权重下降：应用已内嵌 Python sidecar（~40-60MB），外壳占比相对小；OCR/Typst 等大组件按需下载进一步控制体积。
- 钥匙串经 sidecar 的 keyring 库实现（macOS Keychain / Windows 凭据管理器 / Linux Secret Service），不依赖外壳能力。
- 回退条件：若对包体积/内存极度敏感，可切换 Tauri（业务逻辑全在 sidecar，替换外壳不影响后端与前端）。

**（2）本地服务层：Python sidecar**
- 教材解析、OCR、LLM/嵌入客户端 SDK 的生态集中在 Python，MVP 阶段用 Python 效率最高。
- 分发：用 python-build-standalone 内嵌运行时 + PyInstaller 打包为 sidecar 目录（压缩后约 40-60MB），用户零配置；首启自举。
- 边界清晰：所有通信走 localhost HTTP，未来可整体用 Rust 重写而不动前端。

**（3）存储与检索：SQLite + sqlite-vec + FTS5**
- 单机单用户，SQLite WAL 模式支持并发读；单文件便于备份与迁移。
- sqlite-vec 以虚拟表形式提供向量余弦相似度，可与业务表直接 JOIN，删除/更新无索引漂移问题；FTS5 提供 BM25 关键词检索；两者结果用 RRF（Reciprocal Rank Fusion）融合，实现混合检索。
- 容量目标：≥50 万段落、单库 ≤5GB。

**（4）LLM 网关：统一 OpenAI 兼容协议**
- 绝大多数云端（OpenAI/DeepSeek/通义/智谱/Moonshot）与本地（Ollama/LM Studio）都提供 OpenAI 兼容端点；Claude 提供官方 SDK/兼容端点。
- 网关能力：流式输出（SSE）、结构化输出（JSON Schema）、token 统计、超时与重试、能力探测（上下文长度/视觉/长文）。
- 任务级默认模型映射存储在设置中，每个任务记住上次使用的模型。

**（5）任务系统：表驱动异步队列**
- 任务状态机：`pending → running → completed / failed / canceled`，支持 `paused`（断点续跑）。
- 进度心跳 + SSE 推送；取消通过协作式检查点；失败指数退避重试；任务表记录 `params_json`（可复跑）与 `result_ref`。
- 否决 Celery/Redis：本地单机无需独立消息中间件，违反"无额外服务依赖"原则。

**（6）导出：Typst**
- 试卷需要精确排版（题号、答题卡、分页、CJK），Typst 排版质量优于 WeasyPrint 且渲染速度快；便携二进制打包进应用。
- 备选：WeasyPrint（纯 Python，无额外二进制，作为降级路径）。

### 6.3 已否决方案

| 方案 | 否决原因 |
| --- | --- |
| Tauri 2.x | 渲染一致性依赖系统 WebView（Windows WebView2 引导、Linux 系统库）；体积优势因内嵌 sidecar 而弱化 |
| Chroma | 需要独立进程或网络服务，违背"零额外服务" |
| FAISS | 索引文件与业务数据分离，增删改需全量重建策略 |
| Celery / Redis | 本地单机场景过重 |
| PostgreSQL | 单机单用户无需服务端数据库 |
| LangChain | 抽象层过厚，流式/结构化输出/成本统计控制力不足 |
| 内置本地嵌入/重排模型（bge-m3 等） | 体积与 CPU 性能负担；用户自建模型经统一网关即可同等方式接入 |

### 7.1 ER 关系

## 9. AI 能力设计

### 9.1 Prompt 模板
- 每个任务类型一个可编辑模板（出题/总结/答疑/阅卷/教案），变量：`{context}`、`{question}`、`{history}` 等。
- 内置版本与用户版本分离；输出统一要求 JSON Schema 约束（结构化输出）。

### 9.2 RAG 管线（答疑强制）
1. **范围解析**：章节/教材/课程 → `chapter_ids`。
2. **查询改写**（可选）：模型判断是否扩写/拆解。
3. **混合检索**：FTS5 BM25 top-20 ∪ sqlite-vec top-20 → RRF 融合（向量由用户配置的嵌入模型生成）。
4. **重排**（可选）：由用户配置的重排模型（或长上下文模型）完成 → top-5（可配置开关；未配置时跳过）。
5. **上下文组装**：带 `[教材名｜章节｜页码｜段落号]` 标签；token 预算 = 上下文长度 × 0.5。
6. **生成**：系统提示约束"仅依据材料作答并标注引用；材料未覆盖时明确声明"。
7. **引用校验**：模型输出的引用标记必须映射回真实 chunk，否则剔除。

注：向量化（嵌入）与重排均使用用户在模型管理中配置的模型（云端 API 或本地自建），应用不内置任何模型文件。

### 9.3 出题协议
- 输入：章节原文（token 预算滑窗）、题型/数量/难度。
- 输出（JSON Schema）：`{type, stem, options[], answer, explanation, difficulty, source_refs[]}`。
- 校验层：答案唯一性、选项完整性、难度合法、引用存在；不合规自动重试（≤2 次，温度递增）。
- 产物默认进草稿箱。

### 9.4 阅卷协议
- 客观题：规则判分（归一化精确匹配）。
- 主观题：输入题目 + 参考答案 + 评分细则 + 学生作答 → 输出 `{score, max_score, points[{desc, obtained}], deductions[{reason, points}], suggestions[]}`；temperature=0。
- 一致性保护：同一题重复阅卷分数波动 >10% 时提示人工复核；支持"重新评阅"（换模型）。

### 9.5 成本与用量审计
- 每次调用写 `ai_tasks`（tokens_in/out、耗时、成本估算）；设置里维护单价表（可覆盖默认价目）。
- 任务中心与设置页提供月度用量仪表盘。

## 10. 安全与隐私设计

- 后端仅监听 `127.0.0.1` + 随机端口 + 一次性启动令牌；前端经 Electron IPC 获取连接信息。
- API Key：AES-256-GCM 加密存库，主密钥存 OS 钥匙串（keyring 库）；钥匙串不可用时降级为加密配置文件并显式警告。
- Key 不进日志、不出现在错误信息与导出物中。
- 默认不加载任何远程资源；无账号、无遥测（崩溃报告本地日志 + 可选手动导出）。
- `.lumen` 备份可选密码加密。

## 13. 测试策略

- **单元测试**（pytest / vitest）：解析、切分、规则判分、RRF 融合、引用校验、加密。
- **协议测试**：出题/阅卷 JSON Schema 校验；Prompt 模板快照测试。
- **集成测试**：导入 → 总结 → 出题 → 测验 → 阅卷全链路（内存 SQLite + 假 Provider）。
- **人工评测集**：20 份代表性教材（含扫描件、公式、表格）；RAG 引用正确率抽评 ≥90%（50 题）。
- **e2e**（Playwright，Web 模式）：核心页面冒烟。

## 15. 风险与对策

| 风险 | 对策 |
| --- | --- |
| PDF 解析质量差（扫描件/公式） | OCR 可选（PaddleOCR 中文优）；公式区域可选 Pix2Text/Nougat（P2 评估）；允许人工补录 |
| 章节拆分不准 | 优先文档原生结构；提供可视化章节编辑器人工调整 |
| LLM 幻觉（答疑/出题） | 强制 RAG + 引用校验；无出处时强制声明"教材未覆盖" |
| 主观题阅卷不公 | 评分细则 + 得分点输出；temperature=0；波动>10% 提示复核；可换模型重评 |
| 大文件处理卡顿 | 异步任务 + 进程池 + 增量解析；分块向量化；断点续跑 |
| 模型 Key 泄露 | AES-256-GCM + OS 钥匙串；不经过任何服务器 |
| 用户自部署模型显存不足 | 量化模型（Q4/K_M）；CPU 降级；任务级切换；引导用户选型 |
| 长教材超上下文 | 滑窗 + 检索增强；不追求全文一次投喂 |
| 包体积与内存占用（Electron） | 外壳仅渲染、业务在 sidecar；OCR/Typst 等大组件按需下载；必要时回退 Tauri |
| Typst / PaddleOCR 二进制体积 | 按需下载模型与组件；安装包分级（基础包 + 可选组件） |
